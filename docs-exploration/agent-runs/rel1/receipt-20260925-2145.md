## Attempt Log

### Attempt 1
- **Failure Cause:**
  1. `gcloud container clusters create` ran synchronously without progress output and hit client execution timeout.
  2. The `nvidia-dra-driver-gpu` Helm chart (v25.8.0) rejected installation with `execution error at (nvidia-dra-driver-gpu/templates/validation.yaml:39:4): The default value of 'resources.gpus.enabled=true' is not yet supported... Until then, please explicitly set 'resources.gpus.enabled=false' ... If you truly want to force 'resources.gpus.enabled=true' to apply, you must also set 'gpuResourcesEnabledOverride=true'`.
- **Evidence:** Helm install failed immediately during validation templating.
- **Fix:** Made cluster/pool provisioning asynchronous with active status polling in `deploy.sh`, and added `--set gpuResourcesEnabledOverride=true` and GPU taint toleration to the Helm install command.

### Attempt 2
- **Failure Cause:**
  1. `nvidia-dra-driver-gpu-kubelet-plugin` DaemonSet failed pod creation with `insufficient quota to match these scopes: [{PriorityClass In [system-node-critical system-cluster-critical]}]` because system priority classes are restricted to `kube-system` on GKE Standard.
  2. `nvidia-dra-driver-gpu-controller` deployment stayed in `Pending` because default Helm chart node affinity required `node-role.kubernetes.io/control-plane: Exists`, which does not exist on GKE worker nodes.
- **Evidence:** `kubectl describe ds` and `kubectl describe pod` in `nvidia-dra-driver-gpu` namespace showed scheduling failure events.
- **Fix:** Added `--set controller.priorityClassName="" --set kubeletPlugin.priorityClassName="" --set controller.affinity=null` to `deploy.sh`.

### Attempt 3 (Successful)
- **Result:** GKE cluster, GPU DRA node pool, NVIDIA drivers, NVIDIA DRA GPU driver daemonset/controller, Filestore CSI 1TiB PVC, and OpenRL release bundle (`redis-store`, `open-rl-scheduler`, `open-rl-gateway`) deployed cleanly and verified deterministically.

## Deviations from the Runbook

1. **Helm CLI Installation (Attempt 1):**
   - *Constraint:* The execution sandbox did not contain `helm` v3. Installed via official get-helm script before running driver chart installation.
2. **NVIDIA DRA Driver Helm Chart Overrides (Attempts 1 & 2):**
   - *Constraint:* `nvidia/nvidia-dra-driver-gpu:25.8.0` requires explicit opt-in for GPU allocation (`gpuResourcesEnabledOverride=true`), rejects `system-node-critical` priority classes on non-`kube-system` namespaces in GKE, requires removing `node-role.kubernetes.io/control-plane` affinity since GKE managed control plane nodes are unaddressable, and requires tolerations for the GPU node pool taint `nvidia.com/gpu=present:NoSchedule`.
3. **Gateway Deployment & Service Names (Attempt 1):**
   - *Constraint:* Official release manifests (`openrl-lora.yaml`, `openrl-distributed-shared.yaml`) name the API gateway component `open-rl-gateway` and its service `open-rl-gateway-service` (rather than `open-rl-api-server`). Updated rollout status check and smoke test port-forwarding to support both names dynamically.
4. **Cloud Resource Ownership Labeling (Attempt 1):**
   - *Constraint:* GKE cluster creation added `--labels="repo-agent-instance=or-rel1"` to ensure clear ownership auditing.
